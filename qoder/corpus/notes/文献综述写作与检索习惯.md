# 一、为什么要做文献库

写综述时最大的成本不是读论文，而是"找不到读过的那篇"。以前用文件夹分类，文件名混乱，半年后完全检索不到。现在希望把论文和笔记都放进一个库里，用关键词加语义混合检索，三秒内定位到具体段落。

# 二、检索习惯

我习惯用两类词混合搜索：专业术语（例如"消息传递"、"过平滑"）用来精确命中，描述性表述（例如"邻居太多会不会学不出来"）用来找语义相近的段落。关键词检索负责前者，向量检索负责后者。

另外经常需要按年份与标签过滤，例如"只看 2023 年之后的图神经网络相关笔记"。

# 三、复习时的痛点

复习期末的笔记时，完全不记得当初把结论写在哪一篇里，希望系统能记住"我读过什么、读到哪一段"，再次检索时把已经读过的内容标出来或直接跳过。

# 四、工具链设想

1. 导入：把 Markdown 笔记与论文正文切块入库；
2. 检索：全文索引 + 向量索引 + 年份/标签过滤；
3. 摘要：把命中的段落压缩成一段话；
4. 记忆：记住研究方向、检索历史与阅读进度。

# 五、写作规范

每条结论都要能指回原文的段落位置，检索结果必须带出处，否则不敢引用。摘要只允许使用检索到的材料，不允许模型自由发挥。
